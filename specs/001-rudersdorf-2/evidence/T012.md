## What the tests fix for T013 and T014

Where plan.md, data-model.md and the contract leave something open, the tests use only the
listed attributes and fix the following. Each line is a decision of this task.

- **Time passes only through `schritt(dt)`, and `schritt` moves the enemies that
  `erzeuge_gegner` placed while the phase is `bauen`.** No test calls `starte_welle` (T014,
  T015). Building "during a wave" is tested as building while enemies walk, once in the phase
  `bauen` and once with `spiel.phase = "welle"` set by the test (round 1, finding 1). That test
  stops while its enemy is still walking, so the engine never has to end a wave it did not
  start; with `phase == "welle"`, wave 0 and nothing to spawn, `schritt` must simply move the
  enemies (control C09: an engine that ends an empty wave passes).
- **Resources are set through `spiel.dorf.vorraete["gold"]` and `["stein"]`**; village life
  through `spiel.dorf.leben`; the gold in a tower through `bauwerk.ausgegeben`. These must be
  plain writable attributes.
- **`erzeuge_gegner(art, zelle=…)`** puts the enemy at the pixel centre of the cell, appends it
  to `spiel.gegner` and returns it; `rest_weg` is its distance times `ZELLE` from the start.
  Without `zelle` and `start` it appears on the orc gate (tested with one gate). The type of
  `start` is not used by any test.
- **Pixels are map pixels**: `zentrum((s, z)) == (s * ZELLE + ZELLE / 2, z * ZELLE + ZELLE / 2)`,
  the convention the `reichweite` stand-in already uses (`x // 40`).
- **Movement is exact**: on arriving at a cell centre the rest of the step is spent on the next
  cell, so `tempo * t` holds to `1e-6` pixels for `DT`, `2 DT` and `LABOR_DT`, also around
  corners. Mid-step, `ziel_zelle` is the cell being walked into and `zelle` either that cell or
  the one behind it.
- **Swamp**: half speed holds exactly while the enemy is between the centre of the first and the
  centre of the last swamp cell. Where exactly the slow stretch begins and ends is open: the
  test across a whole swamp allows two steps' travel (controls C01 and C02: speed by the cell
  walked into, and by the cell under the pixel, both pass).
- **The village gate is reached at the centre of its cell** (plan: "moves towards the centre of
  `ziel_zelle`; on arrival it asks for the next step"): three steps before that nothing has
  happened, two steps after the computed arrival the breach is done. An enemy created on the
  gate cell breaches within three steps.
- **Events** are dictionaries with `"art"`; `durchbruch` carries `"schaden"`. For `gebaut` and
  `verkauft` only the kind and the count are asserted. `hole_ereignisse()` empties the list.
- **`abstaende()`** has no entry for a built-on cell and is recomputed by `baue` and `verkaufe`.
- **Messages.** A refusal changes `meldung` to a non-empty text. Fixed words: `Weg` when the
  rule refuses for the route, `Gold` and `Stein` when resources are short, `Mission 5` when
  the rule said yes and the safety net refused (and not when the rule itself refused);
  `flusstal` in the fallback message. Four reasons must differ from each other: not buildable,
  an enemy in the way, no route, too little gold. For `pruefe_karte`: `Dorftor`, `Orktor`,
  `Dorf`, `Weg`, the unknown character itself, and the required number of rows or columns.
- **`Spiel(kartentext=…)` raises `ValueError` also for rows of different length**, although the
  reference `lies_karte` raises it inside the workbench, where it arrives as a `Lernfehler` with
  `art == "ValueError"` (plan: "with a broken text raises `ValueError`").
- **`pruefe_karte(raster)` has no workbench**, so it checks the route of each gate itself.
- **A named map whose grid fails validation**: `lade_karte` lets the `ValueError` out,
  `Spiel(karte=…)` plays `flusstal` and names it in `meldung` (round 1, finding 2). The test
  reaches the case through the workbench, not through a file: for the engine a broken grid
  from `lies_karte` and a broken file are the same thing.
- **Hill**: the bonus is in `bauwerk.werte["reichweite"]`; `werte` is the building's own copy.
- **`Bauwerk.ausgegeben`** after `baue` is the gold price; the refund is
  `floor(VERKAUF_ANTEIL * ausgegeben)`.
- **`Gegner`** built directly has the table's values, `effekte == []`, and no `__eq__` of its
  own (two equal orcs are different objects in a list; T009).
- **Workbench per match**: the tests pass `Werkbank("loesung")`, a workbench with one capability
  forced open (`karten`, `wegfindung`, `schadensarten`, `bauregel`), and one for a temporary
  package that re-exports the reference and replaces `darf_bauen`.

## Learnings

Class: guidance (these four and one on counting mutants are in loop.md, *Lessons*; none needs a
sensor or a tool).

- An engine test task writes down, in one section of its evidence, every decision its tests
  take where the plan is silent; the next task reads that section instead of the tests.
- A control mutant ("another legitimate engine") per open design choice shows where a tolerance
  is too tight before the implementer meets it (the swamp test failed the pixel-terrain engine
  by one step's travel).
- A case that seems to need a file in the repository or a later feature usually has a seam in
  the public interface: a broken named map through a workbench whose `lies_karte` spoils it,
  the phase `welle` by setting `spiel.phase` and stopping before the wave could end.
- A refusal test also asserts who refused: where the engine has a net behind the rule, a mutant
  that hands the rule fewer arguments is caught by the net and survives without it.

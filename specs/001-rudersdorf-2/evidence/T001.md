## Harness gaps

- The guard reads import statements and literal dynamic imports. An import whose module name is
  computed at run time (`__import__(name)`), or `exec`, is invisible to it. Matters little: the
  code under guard is written in this repository and reviewed. No cheap sensor; recorded only.
- `rudersdorf/labor` importing `rudersdorf.ansicht` is not forbidden by the task text or
  Constitution III (only `pygame` is), so the guard does not report it. plan.md's dependency
  direction (`labor → kern`) suggests it should be; a labor module that did so would in practice
  be caught through the `pygame` import of the presentation module only at run time. Proposed for
  the owner, not added here (it would be a rule the task does not name).

  Recorded in `loop.md` *Lessons*.

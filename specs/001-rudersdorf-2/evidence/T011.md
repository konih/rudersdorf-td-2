## Decisions taken inside the task

- **`gesamt_tempo_faktor` is the contract's literal rule** (smallest factor of the effects not
  over, `1.0` for none), written with the "smallest so far, `None` at the start" loop that
  `kettenblitz` already uses. A solution that starts at `1.0` passes the tests too; the two
  differ only for a factor above 1, which the game does not have (T010, *Not asserted*).
- **`Betaeubung.__init__` only calls `super().__init__(dauer)`.** The parity guard compares
  methods both ways and the workshop stub ships this method, so the reference must have it. Its
  comment says that it could be left out and why. `Brand` shows the other case: no method at all.
- **`Regeneration` and `Heiler` call `heile` whenever their conditions hold**, also with an
  amount of 0 (zero seconds) and for an enemy at full life; the enemy caps its own life. T010
  left both open.
- **A defeated `Beschwoerer` keeps counting down** and summons at the next call after it lives
  again; the game never revives an enemy, and T010 left `rest` of a defeated carrier open.
- **`Heiler` tells its carrier apart with `is`**, like `kettenblitz` uses `in`: the engine's
  `Gegner` must not define `__eq__` (already noted by T009).
- **Stand-in effects** keep `dauer`, have `rest == 0.0` from the start (consistent with
  `ist_vorbei()` being `True`), and keep the arguments they were created with (`faktor`,
  `schaden_pro_sekunde`; `schadensart` as in the reference). `tick` touches neither the enemy
  nor `rest`. The five classes mirror the reference's hierarchy (`ErsatzBrand(ErsatzGift)`).
- **Stand-in abilities** keep their arguments; the stand-in `Beschwoerer` has `rest` equal to
  the interval and never changes it. None looks at `traeger` or `alle`.
- **Stand-in list functions** never look into the list: they answer the same for entries that
  are no effects.
- **Stand-in `erzeuge_welle`**: `[]` for a catalogue without `ork` and for an orc price of 0 or
  less (a stand-in must never halt or crash a match); `ab_welle` and `boss` of the orc are not
  read; `zufall` is not used and may be `None`. A guard `budget < preis` was removed after a
  mutant showed it redundant (`budget // preis` is 0 or negative there, and a list times that
  is empty); the comment in the code says so.
- **Probes.** The probes of `effekte` and `faehigkeiten` matched the contract's signatures as
  T005 wrote them; no probe was changed. What was missing is a sensor: three tests now run every
  probe of tracks A–C against the reference. The list of solved capabilities is written out in
  the test (`IN_DER_REFERENZ_GELOEST`) and grows with tracks D and E. The probe of `magie`
  (`probiere_zauber`) ends in `wirke`, which raises `NotImplementedError` in the solved base
  class by design: the task that adds `magie` to the list (T026) has to allow for that.

## Learnings

Class: guidance (persisted as lines in loop.md, *Lessons*).

- The workbench ignores every probe error but `NochOffen`, so a probe's call shape can only be
  tested against solved code: run each probe against the reference and fail on any exception,
  and hand the probes a recording module to assert that each class probe calls every public
  method itself (a method reached through another method does not count).
- A stand-in is compared with the reference by `inspect.signature`, name by name and method by
  method: the engine builds objects from data tables with keyword arguments, and the stand-in
  tests of a test task only call positionally.
- A guard clause a mutant shows to be redundant is deleted and replaced by a comment on why the
  remaining expression already covers the case; an unreachable guard in a stand-in is a
  survivor in every later mutation run.
- After the first mutant batch, list the fixed-point tests no mutant reached and write a second
  batch aimed at them; one sweep of "one mutant per clause" left 23 of 166 tests untouched.

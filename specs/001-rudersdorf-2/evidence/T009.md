## Decisions taken inside the task

- **`zufall` stand-in, and why it is not a call counter.** The dispatch note suggested a counter
  that advances on every call. A counter is state outside the match: it would live in the module,
  survive from one match to the next in the same process, and two matches with the same seed
  would then choose differently, which is what plan.md's determinism rule forbids (and what
  T014's state-hash test will compare). The stand-in is therefore a pure function of its
  candidates: it adds up `x + y` of all candidates and takes the whole number modulo the list
  length as the index. Enemies move every step, so the choice keeps changing; nothing is drawn
  from a generator and nothing is remembered, so the same match replays identically. `x` and `y`
  rather than `rest_weg`: positions are always finite numbers, a remaining distance might not be
  for an enemy without a route. The tower's position is not used. Mutant E18 (a call counter)
  and E17 (`random.choice`) both go red on the new tests. The docstring says all this in German.
- **`reichweite` stand-in.** Living enemies only (T008 left defeated enemies open); row and
  column are `y // 40` and `x // 40` compared with the tower's; inside the row or column the
  distance is still the straight line and "within" is `<=`.
- **`kettenblitz` stand-in**: a fresh `[start]`, also when `start` is not in the list.
  **`ausbau` stand-in**: `None`, arguments untouched (as T008 fixed).
- **Reference, distance.** `_abstand(x1, y1, x2, y2)` is written once in `loesung/tuerme.py`
  (Pythagoras, with a comment) and used by `in_reichweite`, `kettenblitz` and, through
  `from .tuerme import _abstand`, by `naechster`. The underscore keeps it out of the parity guard.
- **Reference, strategies.** Named key functions `_rest_weg` and `_leben` for four strategies;
  one `lambda` in `naechster`, where the key needs the tower, with a comment saying what a
  `lambda` is and why it is needed there. The module docstring explains `key` and that `min` and
  `max` keep the earlier element on a tie, which is the contract's tie rule.
- **`gefaehrlichster`.** Border = smallest `rest_weg` + 0.25 × (largest − smallest); candidates
  with `rest_weg <= border` form the vanguard; `max` by `leben`. "Within" is `<=` as everywhere in
  the contract. On T008's lists it differs from each of the five standard rules.
- **`kettenblitz` reference** uses `einer in getroffen`. That compares with `==`; the test double
  and the engine's `Gegner` of plan.md are plain classes without `__eq__`, so it is identity
  (believed for the engine class, which T011 writes).
- **`wende_ausbau_an`** raises `ValueError` with a German sentence naming key and sign.
- **Two new test modules** rather than additions to T008's files: T008's tests stay
  byte-identical. `tests/kern/test_referenz_b.py` imports `loesung.strategien` directly, because
  `gefaehrlichster` exists only in the reference.

## Learnings

Class: guidance (persisted as lines in loop.md, *Lessons*).

- A stand-in that must look random is a pure function of its arguments (here: the candidates'
  positions): a call counter or a module-level generator is state outside the match and breaks
  replay. Prove it with a counter mutant and a `random.choice` mutant.
- A reference-only function (a sixth strategy) gets its own test module that imports `loesung`
  directly; the mission test only checks that some own rule exists.
- Check each hand-written mutant against the test input before the run: a shifted value that
  stays in the same cell is no mutant.

## Decisions taken inside the task

- **Numbers are compared with a tolerance of 1e-9** (`helfer.fast_gleich`), so a solution that
  computes the same value another way (`0.1 + 0.2`) passes. `True`, `None` and text are no numbers.
- **Missions 13 and 14 use a test effect** (`helfer.TestEffekt`), not the learner's classes, so
  they can be solved and checked while mission 12 is open. Kinds are told apart by `name` only,
  as the contract says. The double keeps reporting its factor after it is over; that makes the
  contract's "of all effects that are not over" observable. A solution may ask `ist_vorbei()` or
  read `rest` (controls G04, G05, G12).
- **Inheritance is checked on an object** (`isinstance` and `issubclass` of its type) after
  creating it, because the shipped stubs already declare the hierarchy: a bare `issubclass` test
  would be green before the mission is touched. The behaviour side of inheritance is a subclass
  of the learner's `Gift` defined in the test with only another `schadensart`: it passes only if
  `tick` reads `self.schadensart`, as the contract writes it. No test reads source text.
- **Class attributes.** `name` and `schadensart` are read from the object and from its class,
  because the contract calls them class attributes.
- **Mission 15 is judged by `helfer.wellenfehler`** on a copy of the catalogue taken before the
  call: list of catalogue names; at most `budget // cheapest price` entries (checked first, so an
  absurdly long wave is reported by its length and its first twelve entries); no boss; nothing
  locked; total within budget; nothing allowed still affordable. Beyond that only properties over
  seeds 1–20 are asserted. The order rule ("sorted by name") is asserted as a property: the same
  catalogue written in another order gives the same wave for the same seed. An endless loop
  inside the learner's function cannot be caught; the module docstring tells the learner what to
  look at. All prices in the test catalogues are positive.
- **Stand-in shapes** are fetched with `ersatz_fuer` after an assertion that the entry exists.
  What the tests fix for T011:
  - `schadensarten`: `berechne_schaden(schaden, art, resistenzen)` → `schaden` unchanged for any
    positive damage, whatever the factor (0.4, 2.0, 0.0 or missing); `0` for zero or negative
    damage (a stand-in is weaker, never harmful: no healing by negative damage); `resistenzen`
    untouched.
  - `effekte`, classes `Effekt`, `Frost`, `Gift`, `Brand`, `Betaeubung`: real classes
    (`isinstance(…, type)`), created with the original arguments; `name` as in the contract;
    `tempo_faktor()` is `1.0` before and after any `tick`; `tick(gegner, sekunden)` never calls
    `erleide_schaden` or `heile`; `ist_vorbei()` is `True` from the start (an effect that does
    nothing is over at once, so any clean-up drops it).
  - `effekte`, functions: `fuege_effekt_hinzu(effekte, neu)` leaves the list as it is and
    returns `None` (nothing is ever added or replaced); `gesamt_tempo_faktor(effekte)` is `1.0`
    whatever the list holds and leaves it alone; `raeume_effekte_auf(effekte)` returns a fresh
    `[]` on every call and leaves the argument alone. Together: under the stand-in no enemy
    carries an effect.
  - `faehigkeiten`, classes `Regeneration`, `Heiler`, `Beschwoerer` (also with the default
    `anzahl`): `aktualisiere(traeger, alle, sekunden)` returns a fresh `[]` on every call, calls
    neither `heile` nor `erleide_schaden` on anybody, leaves `alle` alone.
  - `wellen`: `erzeuge_welle(nummer, budget, katalog, zufall)` →
    `["ork"] * (budget // katalog["ork"]["preis"])`, the price read from the catalogue passed
    in, the same for every seed and wave number, `[]` when the budget does not pay one orc
    (zero and negative included), a fresh list, the catalogue untouched.
- **Not asserted, because the spec set leaves it open:** `dauer` and `rest` of a stand-in effect;
  inheritance among the stand-in classes; whether the `wellen` stand-in consumes random numbers;
  the `wellen` stand-in on a catalogue without `ork`; a `tempo_faktor` above 1 (the contract's
  literal "smallest of those not over" would then exceed 1.0; the game has no such effect and
  both natural solutions differ there); attribute names the contract does not fix (`faktor`,
  `schaden_pro_sekunde`, `pro_sekunde`, `radius`, `intervall`, `art`, `anzahl`); whether `Heiler`
  calls `heile` on an enemy at full life (the tests use wounded enemies only); `rest` of a
  `Beschwoerer` whose carrier is defeated.
- **Beyond the task's list, from the contract:** M11 `resistenzen` unchanged; M12 `dauer` stays
  while `rest` counts down, `Effekt(0)` is over, damage goes through `erleide_schaden` exactly
  once (an enemy that halves the damage loses half); M13 the replacing effect takes the old
  one's place, `fuege_effekt_hinzu` returns `None`; M14 `Beschwoerer` neither heals nor hurts;
  M15 `ab_welle == nummer` is unlocked, a price equal to the rest is paid.

## Learnings

Class: guidance (persisted as lines in loop.md, *Lessons*).

- A boundary rule of a base method (floor at 0, negative input ignored) is asserted once per
  subclass, not once on the base: a subclass may override the method, and the inheritance
  assertion does not see that.
- Test fixtures a learner's function could write to (a catalogue, a table) are built fresh per
  test and the answer is judged against a copy taken before the call; a shared module-level
  fixture makes the "argument unchanged" test compare the damage with itself.
- Every call into learner code in a mission test goes through a safe call (`rufe_sicher`,
  `erzeuge`), constructors and methods included; reviewer A reads a bare Python error as missing
  feedback.
- The known-red rows go into loop.md before the review brief is written, not at close.
